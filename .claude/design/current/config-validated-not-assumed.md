`PLAID_ENV` is checked against the SDK's known environments because an unknown value would silently send calls to production. `ENCRYPTION_KEY` is checked for 64 hex chars; stored ciphertext is checked for shape and a rotated key is reported by name. `DATABASE_URL` is checked for a `postgresql://` scheme (the `postgres://` alias, which `pg` equally accepts, also passes — the intent is rejecting non-Postgres schemes, not one spelling) because `pg` reads an unset value as "use libpq defaults" and would quietly query whatever database is listening on localhost. That guard lives once, in the dependency-free `src/lib/env.ts` (`requireDatabaseUrl`), consumed by `src/lib/db.ts` (rethrown as `PublicError` `BAD_CONFIG`), by `drizzle.config.ts` (so migrations can never run against the wrong database) and by the seed script. `PLAID_CLIENT_ID` and `PLAID_SECRET` are checked for presence in `getCredential` because unset values reach Plaid as blank headers and come back as INVALID_API_KEYS, which names neither variable. `PLAID_PRODUCTS` and `PLAID_COUNTRY_CODES` are trimmed and blank-filtered. `.env.local` wins over `.env` everywhere, through the one bootstrap in `scripts/load-env.ts` (imported by scripts and `drizzle.config.ts`; Next loads its own). Config failures throw `PublicError` with code `BAD_CONFIG` so they reach the user; the `DATABASE_URL` check runs at module load, so it surfaces in the dev server log and overlay rather than through `errorResponse`.
