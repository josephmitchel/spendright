Body is `{ cardCategoryId }` or `{ creditCategoryId }`, never both, value a positive integer. Null is a 400 ([[no-category-clear]]). The row is locked `for update` and the account `for share` for both kinds; the account must have a card ([[supported-account-rule]]), a card category must belong to that card, and a category of either kind must not be retired ([[categories-retired-not-deleted]]), each a 400. Rejections inside the transaction are thrown as `PublicError` so it rolls back (confirmed 2026-09-06, replacing the route-local `RejectedRequest` wrapper: one error convention app-wide, and the domain rules stay free of `next/server`). The domain logic lives in `src/lib/categories.ts` (`setTransactionCategory`, with `resolveCategoryPick` holding both kinds' validation side by side); the route only parses the body and maps errors ([[thin-routes-domain-in-lib]]). 55P03 and 40P01 answer `LOCKED` 503 — mapped app-wide in `errorResponse` (confirmed 2026-09-06: any route writing under a lock can lose to a running sync or seed run, so the mapping lives with the error envelope, not in one route); 23503 answers `CATEGORY_REMOVED` 409 route-locally, since the meaning of a broken FK is this route's alone, now reachable only by a hand delete. The response carries the updated row with both category names, minus the raw payload; the kind not written is null by the sign constraint, so no second lookup is made.
